# WIS-013 — Implementar vistas create/edit/show del módulo Cargos

**Tipo:** Feature
**Prioridad:** Alta (bloquea creación manual de cargos desde la UI)
**Reportado:** 2026-05-11
**Detectado durante:** Verificación visual post-WIS-012
**Estado:** Pendiente

---

## Problema

Las vistas `create`, `edit` y `show` del módulo Cargos son placeholders de **0 bytes**, por lo que al navegar a:

- `GET /rh/cargos/create` → pantalla en blanco
- `GET /rh/cargos/{cargo}/edit` → pantalla en blanco
- `GET /rh/cargos/{cargo}` → pantalla en blanco

El backend (Controller, Service, FormRequests, Policy) **ya está implementado** y validado por los tests de importación. Solo falta el frontend.

## Archivos vacíos

```
resources/views/pages/rh/cargos/create.blade.php   (0 bytes)
resources/views/pages/rh/cargos/edit.blade.php     (0 bytes)
resources/views/pages/rh/cargos/show.blade.php     (0 bytes)
```

## Contexto del dominio

### Modelo `App\Models\RH\Position`

Campos `fillable`:
- `institution_id` (uuid, asignado desde `auth()->user()->institution_id`)
- `name` (string, máx 150, único por institución)
- `email` (string, opcional)
- `is_active` (boolean)

Relaciones:
- `emails` → `HasMany(PositionEmail)` — array de correos asociados
- `functions` → `HasMany(PositionFunction)` — array de funciones del cargo
- `contracts` → `HasMany(Contract)` — contratos asociados (solo en `show`)

### Backend ya implementado

- `app/Http/Controllers/RH/PositionController.php` — todos los métodos CRUD
- `app/Http/Requests/RH/CreatePositionRequest.php` — valida `name`, `institution_id`, `is_active`, `emails[]`, `functions[]`
- `app/Http/Requests/RH/UpdatePositionRequest.php`
- `app/Services/RH/PositionService.php`
- `app/Policies/RH/PositionPolicy.php` — roles permitidos: `super-admin`, `admin`, `rh-manager`, `employee-manager`

### Componente existente que sirve de referencia

`resources/views/components/rh/⚡collaborator-form.blade.php` (Livewire SFC) — sigue el mismo patrón que necesitamos para Position. Ver:
- Validación reactiva
- Múltiples secciones del formulario
- Manejo de campos opcionales

## Criterios de aceptación

### Vista `create.blade.php`

1. Formulario Livewire con campos:
   - **Nombre del cargo** (text, requerido, máx 150)
   - **¿Cargo activo?** (toggle, default `true`)
   - **Correos asociados** (lista dinámica, agregar/quitar, validar email)
   - **Funciones del cargo** (lista dinámica de textarea, agregar/quitar)
2. Botón **Cancelar** → vuelve a `/rh/cargos`
3. Botón **Guardar** → llama a `rh.cargos.store`, redirige a `/rh/cargos` con flash `exito`
4. Errores de validación se muestran inline
5. Verifica policy `create` (Position) antes de mostrar (`@can`)
6. Breadcrumb: Inicio › Cargos › Crear

### Vista `edit.blade.php`

1. Mismos campos que `create`, prellenados con el cargo actual
2. Permite agregar/quitar/editar correos y funciones existentes
3. Botón **Guardar** → PUT a `rh.cargos.update`, redirige a `/rh/cargos`
4. Verifica policy `update` (Position) antes de mostrar
5. Breadcrumb: Inicio › Cargos › Editar

### Vista `show.blade.php`

1. Muestra en modo solo lectura:
   - Nombre, estado activo/inactivo
   - Lista de correos
   - Lista de funciones
   - Conteo de contratos vigentes asociados (link a `/rh/contratos?cargo={id}`)
   - Fecha de creación, último cambio
2. Botones: **Editar** (si tiene permiso), **Volver al listado**
3. Breadcrumb: Inicio › Cargos › {nombre del cargo}

## Notas

- El componente `⚡collaborator-form.blade.php` se considera referencia obligatoria de patrón visual y de estructura del SFC Volt.
- Los listados dinámicos (correos, funciones) deben usar arrays Livewire (`public array $emails = []`) con métodos `addEmail()`, `removeEmail($index)`, etc.
- Si el alcance del formulario es muy grande, considerar dividirlo en tabs (Información general / Correos / Funciones) como en `⚡collaborator-form`.
