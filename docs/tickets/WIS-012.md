# WIS-012 — Investigar binding del observer de auditoría (owen-it/laravel-auditing)

**Tipo:** Investigación
**Prioridad:** Alta (afecta trazabilidad y forensia de toda la app)
**Reportado:** 2026-05-07
**Detectado durante:** WIS-011 (corrección de tipo de colaboradores)
**Resuelto:** 2026-05-11
**Estado:** ✅ Cerrado — no era un bug, era configuración por defecto del paquete

---

## Hallazgo

El observer de `owen-it/laravel-auditing` **funciona correctamente** en contexto HTTP/Livewire. Lo que se interpretó como un bug durante WIS-011 era el comportamiento por defecto del paquete: `audit.console = false` desactiva la auditoría en comandos artisan, tinker, jobs en queue worker y cualquier otro contexto CLI.

### Reproducción de la prueba (2026-05-11)

```bash
# 1. Levantar el servidor
composer run dev

# 2. Login en http://127.0.0.1:8000/login
# 3. Editar un colaborador desde /rh/colaboradores/{id}/editar

# 4. Verificar
php artisan tinker --execute='
foreach (\OwenIt\Auditing\Models\Audit::orderBy("created_at", "desc")->limit(5)->get() as $a) {
    echo $a->created_at . " | " . $a->event . " | " . class_basename($a->auditable_type) . " | user_id: " . ($a->user_id ?: "null") . " | url: " . ($a->url ?: "-") . PHP_EOL;
}
'
```

### Resultado de la prueba

```
2026-05-11 09:33:20 | updated | User         | user_id: null | url: http://127.0.0.1:8000/login
2026-05-11 09:31:39 | updated | Collaborator | user_id: 019dfeac-69da-72c8-bc8f-8318a61d8179 | url: http://127.0.0.1:8000/livewire-63192368/update
2026-05-11 09:26:46 | updated | User         | user_id: null | url: http://127.0.0.1:8000/login
```

- ✅ Audit creado para `Collaborator` con `user_id` correcto y `url` registrada
- ✅ Audit creado para `User` durante login (con `user_id=null` esperado: aún no hay sesión)
- ✅ Provider `OwenIt\Auditing\AuditingServiceProvider` registrado vía auto-discovery

### Diagnóstico de configuración

| Item | Valor | Notas |
|---|---|---|
| `audit.enabled` | `true` | OK |
| `audit.console` | `false` | **Causa raíz**: bloquea auditoría en CLI |
| `audit.driver` | `database` | OK |
| `AuditingServiceProvider` | Registrado | OK |
| Modelos `Auditable` | Funcionan en web | OK |

## Resolución aplicada

1. **`config/audit.php`**: cambiar `'console' => false` → `'console' => env('AUDIT_CONSOLE', true)`. Esto activa la auditoría en CLI por defecto, manteniéndola configurable vía variable de entorno.
2. **Tests**: actualizar assertions en `tests/Feature/Console/FixCollaboratorTypesCommandTest.php` para usar `Audit::where('auditable_type', Collaborator::class)->count()` y comparar deltas en lugar de `Audit::count() === 0` (que ahora es falso porque otros modelos sí auditan durante el test).
3. **`FixCollaboratorTypesCommand`**: ya hace `Auth::login()` antes de ejecutar updates, por lo que los audits ahora quedarán correctamente firmados.

## Impacto

- **Web (Livewire/Controllers)**: ningún cambio — ya funcionaba.
- **CLI (artisan commands, jobs, seeders en producción)**: ahora **sí** generarán audits. Esto puede aumentar significativamente el volumen de la tabla `audits` si hay comandos masivos. Mitigación: si esto resulta excesivo, se puede definir `AUDIT_CONSOLE=false` en `.env` y auditar manualmente los comandos críticos vía `\OwenIt\Auditing\Facades\Audit::auditCustom()`.
- **Tests**: ya se ajustaron las 4 assertions afectadas en `FixCollaboratorTypesCommandTest`.

## Notas

- Las hipótesis originales (auto-discovery roto, trait no engancha, conflicto de traits, provider deferred, versión incompatible) **todas resultaron incorrectas**. El paquete funciona como documenta su README.
- La verificación de listeners con `Event::getRawListeners()` mostraba 0 listeners para `eloquent.updated: ...Collaborator` porque owen-it registra el observer vía `Model::observe()` en `bootObservers()`, no como event listener directo. Esto era una pista falsa.
- El `FixCollaboratorTypesCommand` de WIS-011 corrió antes de este fix y **no dejó audits**. Si se requiere trazabilidad histórica de esos 53 updates, se puede correr `Audit::auditCustom()` manualmente referenciando el commit `a305660` como evidencia.
